| SEC-M3-001 | S3 | **A retracted dataset is shown again from cache after the network drops.** When a reachable manifest marks the cached `datasetVersion` as `retracted` and offers no replacement, the app correctly shows "unavailable". The cached record stays in IndexedDB, though, still holding the status it had when cached. If the manifest is later unreachable (offline or flaky mobile network), `loadDataset` shows the retracted dataset with only the "Đang ngoại tuyến" banner. This contradicts ADR-0010 §2 rule 4 and AC-M3-07 ("`retracted` không được nạp"). Retraction is the integrity kill-switch, so students could plan on known-bad times or rooms. Narrow conditions apply (retraction without replacement, then a network failure) and the banner is shown, hence S3 | `apps/web/src/data/loader.ts:130–141`: the offline branch trusts `cached.entry.status`. `loader.ts:145–147` and `:157`: no eviction or tombstone when the manifest says retracted. `loader.test.ts:57` ("…even from cache") only covers the online case. probe2 T3c: after retraction "Chưa xem được thời khóa biểu"; after `route.abort("internetdisconnected")` the Plan and dataset render, and the cached entry status is still `candidate` | When a valid manifest marks a cached version `retracted` (or the term's entry disappears), delete or tombstone the `datasets` record, and refuse tombstoned records in the offline branch. ## Decision

AC-M3-07 holds for hash, schema and domain checks, for the online retracted case and for cache retention. Its retracted-then-offline edge fails (SEC-M3-001). The AC-M3-06 wipe works for the single-tab case, with the edge cases in SEC-M3-006. The seven S3 findings are open under the time-bound exception above.
- Required remediation/retest:
  - Fix SEC-M3-001/002/003 and add tests before G4b/G4a.
  - Fix SEC-M3-004/007 in M5 hosting/hardening, verified in the G4a checklist.
  - Fix SEC-M3-005/006 before M4 G3b.
  - Retest by re-running the probe scenarios: retract-then-offline, encoded traversal, a build with the flag off refusing candidate data, a streaming size cap, AST lint bypass samples, a cross-tab wipe, and header and framing checks on the deployed host.
  - Reopen G3b if the loader, storage, CSP or service-worker contract changes at G1 acknowledgement, or if the working tree changes in those files before commit (hashes above).
